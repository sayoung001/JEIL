# 품질 업무 자동화 시스템

`SPEC.md` (v3) 구현체. 인천 영종하늘도시 A16BL 공동주택 신축공사(`다인영종`) 품질 업무용
Windows 데스크톱 프로그램.

값을 한 번 입력하면 서로 연결된 여러 엑셀이 함께 갱신된다.

| 태스크 | 갱신 대상 | 상태 |
|---|---|---|
| **T-01** 자재검수 회차 생성 | 수불부 체크용 · 갑지 · 자재수불부 (+사진대지) | 구현 |
| **T-02** 사진 분류 | 압축 + EXIF 제거 + 자동 분류 | 구현 |
| **T-03** PHC 겉모양·치수 `Q-Q-02` | 601 일지 · 601 대장 · Q-01,02 실시대장 | 구현 |
| **T-04** PHC 밀크 `Q-Q-01` | 612 일지·사진대지 · 612 대장 · Q-01,02 실시대장 | 구현 |
| **T-05** BSCW/JSP 압축강도 `Q-Q-03/04` | 613 일지 · 시험목록 · Q-03 실시대장 | 구현 (2단계) |
| **T-06** 의뢰시험 `N-02` | N-02 실시대장 | 템플릿만 (§19) |
| **T-07** 서류 투입 | 원본 → 압축분류 / 원본보존 / 글자추출 | 구현 |
| **T-08** 성적서 대장 기입 | 재하·MT 성적서 → O-01,04 실시대장 | 구현 |

## 빠른 시작 (Windows)

```bat
실행.bat                :: 첫 실행 시 가상환경·의존성 자동 설치 후 GUI
현황확인.bat            :: 엑셀을 띄우지 않고 경로·현황·판정·정합성 출력
경로확인.bat            :: 이 PC 에서 어느 폴더를 보고 있는지만 빠르게
build.bat               :: dist\품질자동화.exe 생성
```

`config.yaml` 은 없으면 프로그램이 `config.example.yaml` 에서 자동으로 만든다.
만든 뒤 **경로·인명·업체 별칭**을 그 PC 에 맞게 확인하면 된다.

## 서류 투입 — 원본을 넣으면 갈라 보낸다

`서류투입` 폴더의 칸에 **원본**을 넣고 [미리보기] → [실행] 하면 끝이다.

| 레인 | 대상 | 처리 |
|---|---|---|
| **압축분류** | 자재검수 · PHC_겉모양 · 시료채취 · 물시멘트비 · BSCW · JSP | 촬영정보·GPS 제거 + 긴 변 1600px 압축 |
| **원본분류** | 의뢰시험_재하 · 의뢰시험_MT · 의뢰시험_일반 | **바이트 단위로 그대로** 보존 |
| **성적서** | 성적서_재하 · 성적서_MT · 성적서_생산 · 성적서_의뢰 · 송장 | 글자 추출 → 항목 자동 완성 |

### 왜 의뢰시험만 원본을 지키나

외부 기관이 발급한 **증빙**이라 나중에 원본성이 문제가 될 수 있다.
우리가 찍은 현장 사진은 감리 제출·보관이 목적이라 압축해도 되지만,
남의 성적서와 그 근거 사진은 손대지 않는다.

### ★ 읽기가 먼저, 압축이 나중이다

카카오톡으로 받은 사진은 이미 압축돼 글자가 뭉개져 있다. 그래서

1. **원본을 넣어야 한다.** 카톡으로 받은 것 말고.
2. 프로그램은 **원본에서 먼저 읽고**(`scan`), **그 다음에 압축**한다(`run`).

순서를 바꾸면 읽을 수 있던 것도 못 읽는다. `scan()` 단계에서 이미 추출이
끝나 있는지를 테스트로 못 박아 뒀다.

### 하위폴더가 필요한 칸

폴더 이름이 곧 분류 기준이라 **촬영일로는 맞출 수 없다.**

| 칸 | 폴더 이름 | 예 |
|---|---|---|
| BSCW · JSP | 타설일 | `0822` |
| 물시멘트비 | 시험 회차 | `01` |
| 의뢰시험_재하 | 시험일 동-번호 | `0824 113-152` |

## 성적서 읽기 — OCR 이 아니라 텍스트 추출

진단(PART C §7) 결과 **아이텍 성적서·PHC 생산성적서는 전부 텍스트 레이어를
갖고 있다.** OCR 없이 정확도 100% 로 읽힌다.

```
발급 번호 IS-2026-156157-00      접수 일자 2026.08.24
허용지지력(안전율2.5적용): 1126.0kN/본     <- O-01,04 실시대장 '시험 결과'
채취장소: 113동 No.152
```

| 문서 | 읽는 방법 | 비고 |
|---|---|---|
| 아이텍 MT·재하 성적서 | PDF 텍스트 추출 | 성적서번호·동·말뚝번호·지지력 |
| PHC 생산 시험성적서 | PDF 텍스트 추출 | 601 일지 실측치와 교차 검증용 |
| 자재 송장 | PDF 텍스트 추출 (일부는 OCR) | 업체명은 `vendor_alias` 로 정규화 |
| 스캔본 · 사진 | OCR (**선택 설치**) | 없으면 "OCR 없음" 이라고 분명히 알린다 |

**OCR 엔진은 필수가 아니다.** 없어도 성적서는 읽힌다. 스캔본까지 읽어야 할 때만
`pip install rapidocr-onnxruntime` 을 더하면 된다 (별도 프로그램 설치 불필요).

프로그램이 값을 **단정하지 않는 곳**이 있다. 재하시험에서 허용지지력이 설계지지력
보다 작으면, 시항타는 판정 대상이 아닐 수 있으므로 합·불을 임의로 채우지 않고
사람에게 넘긴다. 확신도가 낮거나 경고가 있으면 대장 기입을 막는다.

## VS Code 에서 실행하기 (노트북)

처음 한 번만 준비하면 다음부터는 **F5** 로 끝난다.

### 준비 (최초 1회)

1. **Python 3.11 설치** — [python.org](https://www.python.org/downloads/) 에서 받는다.
   설치 화면 맨 아래 **`Add python.exe to PATH`** 를 반드시 체크한다.
   확인: 명령 프롬프트에서 `py -3.11 --version`
2. **VS Code 설치** 후 확장 **`Python`** (Microsoft) 을 설치한다.
   이 폴더를 열면 오른쪽 아래에 설치 추천이 뜬다.
3. **폴더 열기** — VS Code 에서 `파일 > 폴더 열기` 로 이 프로젝트 폴더를 연다.
   (`main.py` 가 보이는 그 폴더여야 한다. 상위 폴더를 열면 F5 가 동작하지 않는다.)
4. **의존성 설치** — `Ctrl+Shift+P` → `Tasks: Run Task` → **`의존성 설치`**
   가상환경(`.venv`)을 만들고 필요한 패키지를 넣는다. 몇 분 걸린다.
5. **인터프리터 선택** — `Ctrl+Shift+P` → `Python: Select Interpreter`
   → 목록에서 **`.venv`** 가 붙은 것을 고른다. (보통 자동으로 잡힌다)

### 실행

`F5` 를 누르고 위쪽 드롭다운에서 고른다.

| 항목 | 하는 일 |
|---|---|
| **1. 프로그램 실행 (GUI)** | 평소 쓰는 화면 |
| **2. 경로 확인** | 이 PC 에서 어느 폴더를 보고 있는지. **처음 실행할 때 이것부터** |
| 3. 파일 현황 덤프 | 최신 차수·블록 열·누계 (Excel 없이) |
| 4. 시험 도래 판정 | 배지 내용 |
| 5. 정합성 검사 | 어긋난 곳 찾기 |
| 6. 자세한 로그로 실행 | 문제가 생겼을 때 |

테스트는 왼쪽 **플라스크 아이콘(테스트 탭)** 에서 122개를 그대로 돌릴 수 있다.

### 첫 실행 순서

1. `F5` → **`2. 경로 확인`** 을 먼저 실행한다.
2. 옆에 `config.yaml` 이 자동으로 생기고, 어느 폴더를 보는지 표가 나온다.
3. `quality_root` 가 `[X]` 면 `config.yaml` 을 열어 이 PC 의 경로를 맨 위에 적는다.

   ```yaml
   paths:
     quality_root:
       - 'E:\품질_전체'                       # 노트북 — 먼저 찾는다
       - 'C:\Users\us\Desktop\품질_전체'    # 회사 PC
   ```
4. 다시 `2. 경로 확인` → 전부 `[O]` 가 되면 `1. 프로그램 실행` 으로 넘어간다.

### 자주 막히는 곳

| 증상 | 원인과 해결 |
|---|---|
| `py: 명령을 찾을 수 없습니다` | Python 설치 때 `Add python.exe to PATH` 를 안 했다. 설치 관리자를 다시 열어 `Modify` 로 추가하거나 재설치 |
| `ModuleNotFoundError: PySide6` | 인터프리터가 `.venv` 가 아니다. `Python: Select Interpreter` 에서 `.venv` 선택 |
| 한글이 `???` 로 나옴 | 터미널이 UTF-8 이 아니다. `.vscode/settings.json` 이 처리하지만, 안 되면 터미널에서 `chcp 65001` |
| `경로 확인` 이 전부 `[X]` | `E:\품질_전체` 가 실제로 없거나 이름이 다르다. 탐색기에서 폴더를 복사해 `config.yaml` 에 붙여넣기 |
| GUI 는 뜨는데 **실행**이 안 됨 | 쓰기는 Excel 이 설치된 Windows 에서만 된다. Excel 없이도 **미리보기·경로 확인·현황·판정**은 전부 된다 |
| `xlwings` 오류 | 대상 엑셀 파일이 열려 있다. 전부 닫고 다시 실행 |

> **노트북에서 실제 파일을 건드리지 않으려면** `E:\품질_전체` 대신 사본 폴더
> (예: `E:\테스트_사본`) 를 `quality_root` 맨 위에 적어 두면 된다.
> 백업은 항상 먼저 뜨지만, 연습 단계에서는 사본이 마음 편하다.

## ★ 회사 PC 로 옮기기 (VS Code · 파이썬 없음)

회사 PC 에는 **아무것도 설치하지 않는다.** 노트북에서 만든 폴더를 복사만 한다.

```
노트북            build.bat 실행
                  -> dist\회사PC로_복사할것\
                       품질자동화.exe
                       처음설정.bat
                       자가점검.bat
                       배포안내.txt

회사 PC           위 폴더를 통째로 복사
                  처음설정.bat 더블클릭
                     · config.yaml 생성
                     · 서류투입 폴더 14칸 생성
                     · 자가 점검
                  X 표시가 있으면 config.yaml 의 경로를 고치고 다시 실행
                  품질자동화.exe 더블클릭
```

### exe 가 스스로 진단한다

회사 PC 에는 개발 도구가 없으니 **무엇이 빠졌는지 프로그램이 말해야 한다.**

```bat
품질자동화.exe --selftest
```

확인하는 것: 부품(엑셀 읽기/쓰기·사진·PDF·화면) 설치 여부, **실제로 동작하는지**
(PDF 에서 글자를 뽑아 보고 사진을 압축해 봄), 쓰기 권한, exe 안의 자원,
설정 경로, OCR 유무. GUI 의 **[자가 점검]** 버튼도 같은 일을 한다.

필수와 선택을 구분해서 보여 준다. Excel 이 없으면 기록은 못 하지만
미리보기·경로 확인·현황·판정은 그대로 된다고 알려 준다.

## ★ 만드는 PC 와 쓰는 PC 가 다를 때

exe 는 노트북에서 만들고 회사 PC 에서 돌린다. 품질 폴더 위치가 서로 다르므로
**경로를 exe 안에 굳히지 않는다.** 실행할 때마다 exe 옆 `config.yaml` 에서 읽는다.

### 경로는 PC 별 후보를 적어 둔다

```yaml
paths:
  quality_root:
    - 'C:\Users\us\Desktop\품질_전체'   # 회사 PC
    - 'E:\품질_전체'                       # 노트북
```

위에서부터 찾아 **그 PC 에 실제로 있는 것**을 고른다. 파일 하나로 두 PC 를 모두 쓴다.

| 규칙 | 동작 |
|---|---|
| 1순위 | 실제로 존재하는 첫 후보 |
| 2순위 | 없으면, 상위 폴더가 있는 첫 후보 (아직 안 만든 백업 폴더 등) |
| 3순위 | 그것도 없으면 마지막 후보 |
| 덮어쓰기 | 환경변수 `QUALITY_ROOT` 가 있으면 후보보다 먼저 |
| `{app_dir}` | 프로그램(exe)이 놓인 폴더. 어느 PC 에든 있으므로 마지막 후보로 안전하다 |

### 회사 PC 로 옮기는 순서

1. 노트북에서 `build.bat` → `dist\품질자동화.exe`
2. **exe 하나만** 회사 PC 로 복사 (다른 파일 필요 없음 — 자원은 exe 안에 들어 있다)
3. 처음 실행하면 옆에 `config.yaml` 이 자동으로 생긴다
4. 프로그램의 **[경로 확인]** 버튼을 눌러 전부 `O` 인지 본다
5. `X` 가 있으면 `config.yaml` 의 해당 경로를 그 PC 기준으로 고친다

경로가 안 맞아 GUI 가 안 뜨면 명령 프롬프트에서:

```bat
품질자동화.exe --paths
```

### exe 안 / exe 옆

`--onefile` 은 실행할 때마다 임시 폴더에 풀렸다가 **끝나면 지워진다.**
그래서 남아야 하는 것은 전부 exe 옆에 둔다.

| 위치 | 무엇이 | 성질 |
|---|---|---|
| **exe 안** (`sys._MEIPASS`) | `workflows/`, `templates/`, `config.example.yaml` | 읽기 전용. 실행이 끝나면 사라진다 |
| **exe 옆** (`sys.executable` 폴더) | `config.yaml`, `state.json`, `logs/` | 사람이 고치고, 다음 실행까지 남는다 |

`core/paths.py` 가 이 둘을 갈라 준다. `templates\현장시험\새시험.yaml` 을 **exe 옆에**
같은 경로로 두면 exe 를 다시 만들지 않고도 항목을 추가할 수 있다 (옆이 안보다 우선).

## CLI

```bash
python main.py             # GUI
python main.py --selftest  # 이 PC 에서 돌 수 있는지 점검 (새 PC 첫 실행)
python main.py --setup     # 서류투입 폴더 만들기
python main.py --intake    # 서류투입 폴더를 훑어 계획만 보기
python main.py --intake --run   # 실제로 분류
python main.py --paths     # 어느 폴더·파일을 보고 있는지 (경로 문제 1순위)
python main.py --dump     # 세 파일의 최신 차수·블록 열·누계 출력 (읽기 전용)
python main.py --check    # 시험 도래 판정 (배지 내용)
python main.py --verify   # 정합성 검사 (§21.3)
```

`--dump` · `--check` · `--verify` 는 **Excel 없이** 돈다. 사용자가 그 파일을 열어 둔 채여도 방해하지 않는다.

### 왜 `SheetPort` 를 뒀나

쓰기 엔진이 xlwings API 를 직접 부르면 Excel 없이는 한 줄도 검증할 수 없다.
엔진은 `SheetPort` 만 알고 백엔드가 둘이라서,

* **[미리보기]** 가 표시용 별도 코드가 아니라 **실행과 같은 경로**를 탄다.
* 갑지 `DG` 블록 · 수불부 누계 체인 · 실시대장 병합 패턴 같은 좌표 규칙을
  Excel 없이 테스트로 못 박을 수 있다 (104개 테스트).

## 반드시 지킬 것

1. **쓰기는 xlwings 전용.** openpyxl 로 저장하면 EMF 이미지와 VML 도형이 조용히 사라진다.
   Excel 이 없으면 **작업을 중단한다.** 폴백 저장은 없다.
2. **`.xls` 4개는 확장자를 바꾸지 않는다.** 감리단 제출 파일이다. `FileFormat` 을 건드리지 않는다.
3. **백업 실패 = 작업 중단.** 예외 없음.
4. **누계 수식을 상수로 박지 않는다.** 직전 데이터 행을 실제로 찾아 참조를 만든다.
5. **업체명은 `vendor_alias` 를 거친다.** 파일마다 표기가 다섯 가지다.
6. **모르는 업체명을 조용히 무시하지 않는다.** 그러면 그 업체는 영원히 시험 대상에서 누락된다.
